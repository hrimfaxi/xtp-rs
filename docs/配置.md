# 配置参考

> [← 返回 README](../README.md) · 相关：[工作原理](./工作原理.md) · [部署](./部署.md) · [OpenWrt 部署](./OpenWrt.md)

xtp-rs 的程序配置为 TOML 文件，默认路径 `./config.toml`，可用 `-c` 指定：

```bash
xtp-rs -T -c /etc/xtp-rs/config.toml   # 校验并打印生效配置（类似 sshd -T），检查通过后退出
xtp-rs    -c /etc/xtp-rs/config.toml   # 正式启动
```

完整可复制模板见 [contrib/etc/xtp-rs/config.toml](../contrib/etc/xtp-rs/config.toml)。

> [!NOTE]
> 本文的默认值以 `src/cli.rs` 中的 `default_*` 函数为准。除特别说明外，所有字段均可省略。

---

## 一、核心参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `listen` | string | `"[::]:10810"` | TPROXY 监听地址（须与部署脚本的 `XTP_TPROXY_PORT` 一致） |
| `udp` | bool | `true` | 是否启用 UDP 转发 |
| `fwmark` | u32 | `2` | 直连 / SOCKS5 出站 socket 使用的 fwmark（必须等于 `XTP_BYPASS_MARK`，见 [工作原理](./工作原理.md#一整体架构)） |
| `socks5_user` | string | 无 | SOCKS5 认证用户名（需与 `socks5_password` 同时配置） |
| `socks5_password` | string | 无 | SOCKS5 认证密码（需与 `socks5_user` 同时配置） |
| `mmdb_path` | string | 无 | GeoIP2 Country 数据库路径（留空禁用国家判定） |
| `direct_countries` | [string] | `["CN"]` | 直连的国家代码（ISO 3166-1 alpha-2） |
| `force_socks5_ips` | [string] | `[]` | 强制走代理的 IP / CIDR（IP 规则中最高优先级） |
| `force_direct_ips` | [string] | `[]` | 强制直连的 IP / CIDR（优先级低于 `force_socks5_ips`） |
| `force_socks5_ips_file` | string | 无 | 额外的强制代理 IP / CIDR 文件路径（每行一个） |
| `force_direct_ips_file` | string | 无 | 额外的强制直连 IP / CIDR 文件路径（每行一个） |
| `force_socks5_domains` | [string] | `[]` | 强制走代理的域名（域名规则中优先级最高） |
| `force_direct_domains` | [string] | `[]` | 强制直连的域名（优先级高于 geosite，低于 `force_socks5_domains`） |
| `direct_local_ip` | bool | `true` | 回环 / 链路本地地址是否强制直连 |
| `sniff_tls_sni` | bool | `false` | 是否启用 TLS SNI 嗅探（TCP） |
| `sniff_http_host` | bool | `false` | 是否启用 HTTP Host 嗅探 |
| `quic_sniff_mode` | string | `"none"` | QUIC SNI 嗅探模式：`none` / `besteffort` / `full` |
| `quic_sniff_pending_timeout_ms` | u64 | `200` | `full` 模式 pending 缓存等待时限（毫秒），详见下文 |
| `proxy_mode` | string | `"smart"` | 代理模式：`smart` / `global` / `bypass`（`SIGUSR1` 可临时切换，`SIGHUP` 后恢复） |
| `geosite_path` | string | 无 | geosite.dat 文件路径（需编译 `geosite` feature） |
| `proxy_geosite_tags` | [string] | `[]` | 走代理的 geosite 分类（如 `gfw`） |
| `direct_geosite_tags` | [string] | `[]` | 走直连的 geosite 分类（如 `geolocation-cn`） |
| `log_level` | string | 无（环境变量，否则 `info`） | 日志级别：`error` / `warn` / `info` / `debug` / `trace` |
| `udp_session_timeout_secs` | u64 | `120` | UDP 会话空闲超时（秒），按双向活动判定，必须 > 0 |
| `socks5_udp_reply_watchdog_secs` | u64 | `31` | SOCKS5 UDP relay 回包静默看门狗（秒），见下文 |
| `connect_timeout_secs` | u64 | `20` | 上游连接超时（秒），必须 > 0 |
| `splice` | bool | `false` | TCP 转发是否优先使用 splice 零拷贝（为 `true` 时半关闭看门狗不生效，见 [工作原理](./工作原理.md#六tcp-relay-半关闭静默超时)） |
| `half_close_timeout` | u64 | `600` | TCP relay 半关闭静默超时（秒），`0` 禁用；仅在一方已半关闭后计时 |
| `route_cache_ttl_secs` | u64 | `5` | 路由结果缓存 TTL（秒），0 禁用缓存 |
| `route_cache_max` | usize | `4096` | 路由结果缓存最大条目数（direct / upstream 缓存各自独立上限） |

> [!NOTE]
> 嗅探功能默认关闭，需在运行配置中手动开启；默认构建包含各项嗅探功能。启用后会增加协议解析开销，部分情况下还会等待更多数据。实际开销取决于协议、嗅探模式和流量特征。

### SOCKS5 UDP relay 看门狗

`socks5_udp_reply_watchdog_secs`（默认 31 秒）：session 建立后若在此时间内没收到任何回包，主动取消 session，让客户端下一个包触发重建（重新 ASSOCIATE），用于清理失效的僵尸 relay session。仅对 SOCKS5 出站生效，`0` 表示禁用。旧名 `udp_session_idle_timeout_secs` 保留为兼容 alias，建议迁移到新名。

### QUIC 嗅探模式

`quic_sniff_mode` 三种模式：

- **`none`**（默认）：不执行 QUIC 嗅探，也不引入嗅探等待，UDP 包按 IP 路由转发；
- **`besteffort`**：对每个新建 UDP 会话的首个数据包尝试提取 SNI。成功时，将域名用于直连 / 代理判定，并在需要代理时用于上游分组选择；首包不足或解析失败时不再等待后续包，按 IP 路由；
- **`full`**：首包不足以完成嗅探、需要继续收集数据时，将数据包暂存到 pending 缓存。成功提取 SNI 后，使用域名完成路由判定并转发缓存的数据包；超时或解析失败时，按 IP 路由转发。跨包识别率更高，但可能引入等待。

`full` 模式的缓存等待时限由 `quic_sniff_pending_timeout_ms` 控制（默认 **200 ms**，与 xray-core 的 `cacheDeadline` 同量级）：仅当 ClientHello 跨多个包时才缓存等待补齐，窗口内凑齐即立即转发；首包即可完成嗅探时解析后直接转发，不进入 pending；超过时限仍未凑出则放弃 pending，按原始 IP 转发。设为 0 时 pending 创建即失效，行为退化为近似 `besteffort`。

pending 缓存上限（代码常量，不可配置）：每个 pending 会话最多缓存 8 个 UDP 数据报，累计大小不超过 64 KB；全局最多保留 4096 个 pending 会话。解析 QUIC Initial 会增加 CPU 开销，低配设备可按需选择模式。

`besteffort` 放弃时 debug 日志会打印：

```text
UDP sniff best-effort: SNI not found in first packet, giving up (no further reassembly), forwarding by IP
```

## 二、上游配置

```toml
[[upstream]]
id = "server1"                  # 唯一标识（不可重复、不可为空）
addr = "192.168.1.100:1080"     # SOCKS5 地址
# groups = ["default"]          # 所属分组，未设置则自动属于 ["default"]
# gain = 1.0                    # 乘数因子（必须为有限正数），放大/缩小该上游的动态分数
```

- 至少配置一个 `upstream`；
- `groups` 用于配合 `client_routes` 等实现分组路由，一个上游可属于多个组；
- 配置中若没有任何上游属于 `default` 组且未配置任何 `client_*_routes`，启动会直接报错。

> [!NOTE]
> `groups` 仅定义上游所属分组；自定义分组还需要相应的客户端路由规则，才会参与对应流量的上游选择。

## 三、上游动态评分参数

机制详见 [工作原理 · 上游动态评分机制](./工作原理.md#五上游动态评分机制)。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `disable_upstream_score` | bool | `false` | 禁用动态评分（启用后完全随机选择） |
| `upstream_switch_tolerance` | u32 | `0` | 粘性切换容忍度（分），0 表示不启用粘性 |
| `quic_weight` | u32 | `40` | QUIC 探针在选路分数中的权重百分比（0-100） |
| `quic_stale_secs` | u64 | `180` | QUIC 探针分数过期阈值（秒，范围 10-3600），超期后线性衰减到最低分 10 |
| `enable_relative_scoring` | bool | `false` | 启用跨链路相对归一化评分 |
| `relative_rescore_interval_secs` | u64 | `2` | 相对归一化评分重算间隔（秒），仅相对模式生效，必须 > 0 |
| `upstream_score_debug_interval_secs` | u64 | `0` | 分数调试打印间隔（秒），仅 debug 级别生效，0 禁用 |
| `pick_stats_window_secs` | u32 | `0` | 上游选中统计窗口（秒），每 60 秒打印一次 INFO 日志，0 禁用，最大 604800 |

## 四、健康检查

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `health_check_interval_secs` | u64 | `0` | 主动健康检查间隔（秒），0 表示禁用 |
| `health_check_timeout_secs` | u64 | `5` | 单次健康检查超时（秒） |
| `health_check_fail_threshold` | u32 | `2` | 连续失败次数阈值，启用健康检查时必须 > 0 |
| `health_check_url` | string | `"cp.cloudflare.com"` | 健康检查目标（通过 SOCKS5 发起 HTTP HEAD 探测） |

健康检查通过 SOCKS5 对目标发起 HTTP HEAD 探测，连续失败达到阈值后惩罚该上游；恢复后重新参与上游选择，并把其 TCP 分重置为 300。被动评分（吞吐 + 探针）发现“变慢”，主动检查发现“挂了”。

## 五、客户端路由配置

```toml
# 按客户端源 IP 分配 upstream 分组
[client_routes]
"192.168.1.100" = "group_a"
"192.168.2.0/24" = "group_b"
"2409::/16" = "group_b"          # IPv6 大段也可作为键

# 按客户端源 IP + 域名模式分配 upstream 分组
# 域名支持两种匹配模式：
#   ".example.com"：后缀匹配，匹配 example.com 及其所有子域名
#   "example.com" ：精确匹配，仅匹配 example.com
[client_domain_routes."192.168.1.100"]
".google.com" = "proxy_group"
"example.com" = "direct_group"

# 按客户端源 IP + 目的 IP/CIDR 分配 upstream 分组
# 优先级最高（高于 client_domain_routes / client_routes）
[client_dst_ip_routes."192.168.1.0/24"]
"172.253.118.0/24" = "proxy_group"
```

- `client_routes`：按客户端源 IP 分配分组，支持单 IP 和 CIDR（v4 / v6）；
- `client_domain_routes`：按客户端源 IP + 域名模式分配分组，需要域名嗅探；
- `client_dst_ip_routes`：按客户端源 IP + 目的 IP / CIDR 分配分组，**优先级最高、不依赖嗅探**；
- 域名匹配按后缀长度降序优先；IP / CIDR 按最长前缀优先；
- 客户端前缀从长到短逐表查找：更具体的网段（如 `/32`）只覆盖它显式列出的域名 / 目的网段，未列出的回退到更宽网段（如 `/24`）的表；
- 分组查找顺序：`client_dst_ip_routes → client_domain_routes → client_routes → default`；
- 启动时 `-T` 会校验引用的分组是否存在且非空。

## 六、端口转发

```toml
[[port_forward]]
name = "dns-via-socks5"       # 可选，仅用于日志
bind = "127.0.0.1:5353"       # 本地监听地址
remote = "8.8.8.8:53"         # 远端目标（必须是 IP:PORT，不支持域名）
network = "both"              # tcp / udp / both
```

端口转发规则独立于 TPROXY 监听，收到的数据**无条件**经 SOCKS5 转发到 `remote`。`bind` 不得与 `listen` 地址冲突（启动校验会报错）。

## 七、嗅探参数

### TLS 嗅探

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `tcp_peek_buffer_size` | usize | `32768` | TCP 首包 sniff 全局缓冲区上限（字节），约束 TLS / HTTP 的实际探测长度 |
| `tls_sniff_peek_len` | usize | `2048` | TLS sniff 首次 peek 长度（字节） |
| `tls_sniff_max_len` | usize | `32768` | TLS sniff 最大探测长度（字节） |
| `tls_sniff_max_retries` | usize | `5` | TLS sniff 最大重试次数 |
| `tls_sniff_wait_more_ms` | u64 | `100` | TLS sniff 等待更多数据时间（毫秒） |
| `tls_sniff_timeout_ms` | u64 | `1000` | TLS sniff 总超时时间（毫秒） |

### HTTP 嗅探

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `http_sniff_peek_len` | usize | `512` | HTTP sniff 首次 peek 长度（字节） |
| `http_sniff_max_len` | usize | `16384` | HTTP sniff 最大探测长度（字节） |
| `http_sniff_max_retries` | usize | `5` | HTTP sniff 最大重试次数 |
| `http_sniff_wait_more_ms` | u64 | `100` | HTTP sniff 等待更多数据时间（毫秒） |
| `http_sniff_timeout_ms` | u64 | `1000` | HTTP sniff 总超时时间（毫秒） |

> [!NOTE]
> 实际生效的最大探测长度还受 `tcp_peek_buffer_size` 约束，即 `min(各自 max_len, tcp_peek_buffer_size)`。

## 八、校验规则速查

启动（或 `-T`）时会校验以下约束，违反即报错：

- `upstream` 非空，`id` 唯一且非空，`gain` 为有限正数；
- `quic_weight` ∈ 0..=100；`quic_stale_secs` ∈ 10..=3600；
- `udp_session_timeout_secs > 0`、`connect_timeout_secs > 0`；
- 启用健康检查时 `health_check_fail_threshold > 0`；
- `pick_stats_window_secs <= 604800`；
- 启用相对评分时 `relative_rescore_interval_secs > 0`；
- 所有 `client_*_routes` 的键为合法 IP / CIDR，引用的分组存在且非空；
- `port_forward.bind` 不与 `listen` 冲突；
- 若没有任何上游属于 `default` 组，则必须配置至少一条 `client_*_routes`，否则报错。
