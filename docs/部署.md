# 透明代理环境部署（Linux 通用）

> [← 返回 README](../README.md) · 相关：[配置参考](./配置.md) · [工作原理](./工作原理.md) · [OpenWrt 部署](./OpenWrt.md)

本文面向使用 systemd 的通用 Linux 环境（Debian / Ubuntu / Arch / 各类软路由发行版等），需要提权的命令以 `sudo` 为例。OpenWrt 的 UCI 配置、procd 服务管理和日志查看方式请参阅 [OpenWrt 部署](./OpenWrt.md)，不要直接套用本文对应章节的命令。

xtp-rs 本体只负责代理与调度；它要生效，还需要在系统里配好 **nftables + 策略路由（TPROXY）** 和 **旁路 fwmark**。本节全部围绕这套环境。

---

## 一、前置条件

- Linux 内核需启用 TPROXY 相关支持，并提供 `nft_tproxy`、`nft_socket`（`nf_socket`）内核模块。
- 需要 `nftables`、`iproute2`（`ip` 命令）、`curl` 或 `wget`（更新 chnroute 列表时用）。
- 需要 root 权限，或 `CAP_NET_ADMIN` + `CAP_NET_RAW` + `CAP_NET_BIND_SERVICE`。

---

## 二、脚本一览

项目 `contrib/usr/libexec/xtp-rs/` 目录下提供了以下脚本：

| 脚本 | 作用 |
|------|------|
| `common.sh` | 公共函数库与常量，被其他脚本 source |
| `setup-xtp-rs.sh` | 一键配置 nftables 规则 + 策略路由（需 root） |
| `unsetup-xtp-rs.sh` | 一键清理上述规则 |
| `update-chnroute.sh` | 下载并生成中国大陆 IPv4 / IPv6 直连列表（可选） |
| `stats_reporter.sh` | ShadowQUIC 性能上报 daemon 主脚本（见 [OpenWrt 部署](./OpenWrt.md) 或 [配置参考](./配置.md)） |

---

## 三、快速部署 / 清理

```bash
cd contrib/usr/libexec/xtp-rs

# 1. 配置透明代理环境（路由表、策略路由、nftables 规则）
sudo ./setup-xtp-rs.sh

# 2. 启动 xtp-rs（另开终端或后台运行）
sudo xtp-rs -c /etc/xtp-rs/config.toml

# 3. 停止 xtp-rs 后清理环境
sudo ./unsetup-xtp-rs.sh
```

`setup-xtp-rs.sh` 会幂等地完成：

- 路由表 ID `100`，添加 `local default dev lo` 路由（IPv4 + IPv6）；
- 策略规则：`fwmark 1` 查找路由表 `100`；
- nftables 表 `inet xtp-rs`：在 `prerouting`（转发的入站流量）和 `output`（本机出站流量）链中匹配 TCP 80/443 与 UDP 53/443，**打 `fwmark = 1`** 使其走策略路由；
- xtp-rs 自身出站连接设置 `SO_MARK = 2`（`XTP_BYPASS_MARK`），nftables 遇 `meta mark 2` 直接放行，**避免代理流量被再次劫持形成环路**。

> [!WARNING]
> **fwmark 约定**：配置文件里的 `fwmark` **必须等于脚本中的 `XTP_BYPASS_MARK`（默认 `2`）**，且绝不能等于 nftables 用于标记“待代理”流量的 `XTP_FWMARK`（默认 `1`）。否则 xtp-rs 自己的出站请求会被再次劫持，形成环路，表现为“一启动全网断”。

## 四、可调参数

### 4.1 脚本常量（改 `common.sh`）

以下常量在 `common.sh` 顶部集中定义，修改后需重跑 `setup-xtp-rs.sh`：

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `XTP_TABLE_ID` | `100` | 策略路由表 ID |
| `XTP_FWMARK` | `1` | nftables 给“待代理”流量打的标记 |
| `XTP_BYPASS_MARK` | `2` | xtp-rs 出站连接的旁路标记，须与配置 `fwmark` 一致 |
| `XTP_TPROXY_PORT` | `10810` | TPROXY 监听端口，须与配置 `listen` 的端口一致 |
| `XTP_TABLE_NAME` | `xtp-rs` | nftables 表名 |

### 4.2 环境变量（无需 uci，通用 Linux 直接使用）

非 OpenWrt 系统没有 `uci`，直接用环境变量覆盖脚本行为：

```bash
sudo XTP_TCP_PORTS="80 443 8080" XTP_UDP_PORTS="53 443" ./setup-xtp-rs.sh
```

| 环境变量 | 默认 | 说明 |
|----------|------|------|
| `XTP_PROXY_INGRESS_IFACES` | 自动检测（最终回退 `br-lan`） | 允许进入 TPROXY 的入口接口，空格分隔多个 |
| `XTP_TCP_PORTS` | `80 443` | 待代理 TCP 目的端口（空白 / 逗号 / 分号分隔） |
| `XTP_UDP_PORTS` | `53 443` | 待代理 UDP 目的端口 |
| `XTP_EXT_RESERVED_IP` | 空 | 额外强制直连的目的地址 / IP / CIDR（如上游 VPN IP） |
| `XTP_BYPASS_SADDR` | 空 | 源 IP 直连列表，命中即跳过代理 |
| `XTP_BYPASS_SKUID` | 空 | 按进程属主（用户名或 uid）跳过代理，防环路替代方案 |
| `XTP_BYPASS_CHNROUTE` | `0` | 是否启用中国大陆 IP 直连（`1` / `true` / `yes` / `on`） |
| `XTP_CHNROUTE_URL` / `XTP_CHNROUTE_FILE` | GitHub raw / `/etc/xtp-rs/chnroute.nft` | IPv4 列表来源与输出路径 |
| `XTP_CHNROUTE6_URL` / `XTP_CHNROUTE6_FILE` | GitHub raw / `/etc/xtp-rs/chnroute6.nft` | IPv6 列表来源与输出路径 |

> [!NOTE]
> 非法项会被忽略并打印告警；端口列表全部无效时回退内置默认值。取值优先级：环境变量 > （OpenWrt 的）UCI 选项 > 内置默认。

#### 中国大陆 IP 直连（`XTP_BYPASS_CHNROUTE`）

TPROXY 会把被截获的流量导入本机 input 路径，这些流永远到不了 forward hook，因此 **fw4 flowtable 软 / 硬 offload 对被代理流量无效**。开启本选项后，目的地址命中中国大陆 IP 列表的流量在 `prerouting` / `output` 中提前直连放行：国内流量不再被代理（更低延迟与 CPU 开销），且重新走 FORWARD 路径，offload 得以生效。

```bash
# 1. 生成列表（需能访问 GitHub，可用 XTP_CHNROUTE_URL / XTP_CHNROUTE6_URL 指定镜像）
sudo ./update-chnroute.sh

# 2. 应用规则（开启环境变量）
sudo XTP_BYPASS_CHNROUTE=1 ./setup-xtp-rs.sh

# 3. 建议加入 cron 定期刷新并重跑 setup（只更新文件不重跑 setup 不生效）：
#    30 4 * * 0,3 { /usr/libexec/xtp-rs/update-chnroute.sh && /usr/libexec/xtp-rs/setup-xtp-rs.sh; } >/dev/null 2>&1
```

说明：

- 列表文件位于 `/etc/xtp-rs/chnroute.nft`（IPv4）与 `/etc/xtp-rs/chnroute6.nft`（IPv6）；
- 两个地址族相互独立：任一列表缺失或下载失败只跳过对应规则并告警，不影响其余功能；
- 改动列表后必须重跑 `setup-xtp-rs.sh` 才会应用。

#### 额外直连网段（`XTP_EXT_RESERVED_IP`）

在内置保留网段（RFC1918 等）之外，把指定**目的地址**强制直连，例如上游 VPN 服务器 IP、内网服务器：

```bash
sudo XTP_EXT_RESERVED_IP="10.8.0.1 192.168.9.0/24" ./setup-xtp-rs.sh
```

#### 源 IP 直连（`XTP_BYPASS_SADDR`）

源地址命中列表的流量（如内网管理段）在 `prerouting` / `output` 中提前 return，不进入 TPROXY：

```bash
sudo XTP_BYPASS_SADDR="10.2.1.0/24 192.168.9.0/24" ./setup-xtp-rs.sh
```

#### 按进程属主跳过代理（`XTP_BYPASS_SKUID`）

防环路的替代方案：让 xtp-rs 以专用用户运行并设置本变量后，output 链中属主为该用户 / uid 的本机出站流量提前 return：

```bash
sudo XTP_BYPASS_SKUID=xtp-rs ./setup-xtp-rs.sh
```

- 取值为用户名或数字 uid，用户名不存在时告警并忽略；
- 填 `0`（root）会放行**所有** root 进程的本机出站流量，等于关闭本机出站代理（脚本会额外告警），一般只应填专用低权用户。

## 五、systemd 服务

仓库提供了 `contrib/etc/systemd/system/xtp-rs.service`，把进程托管交给 systemd：

```bash
sudo install -m 0644 contrib/etc/systemd/system/xtp-rs.service /etc/systemd/system/
sudo install -d /etc/default
sudo install -m 0644 contrib/etc/default/xtp-rs /etc/default/xtp-rs   # 可选环境文件
sudo install -m 0755 contrib/usr/libexec/xtp-rs/*.sh /usr/libexec/xtp-rs/
sudo systemctl daemon-reload
sudo systemctl enable --now xtp-rs
```

服务脚本要点：

- `ExecStartPre` 先跑 `xtp-rs --check -c /etc/xtp-rs/config.toml`，配置有错就中止，避免带错配置反复重启；
- `ExecStartPost` 在主进程就绪后调用 `setup-xtp-rs.sh` 添加透明代理规则；
- `ExecStop` 先跑 `unsetup-xtp-rs.sh` 清理规则，再停进程；
- `ExecReload` 发送 `SIGHUP` 热重载；
- 使用 `DynamicUser` + `NoNewPrivileges` + capabilities 约束权限。

`/etc/default/xtp-rs` 可放置环境变量（如 `XTP_BYPASS_CHNROUTE=1`），供 `setup-xtp-rs.sh` 读取。

---

## 六、权限与 capabilities

`contrib/etc/capabilities/xtp-rs.json` 定义了运行所需的最小 capability 集合，可用于 systemd、procd / ujail 或 `setcap`，使进程无需以 root 全权运行。透明代理通常需要 `CAP_NET_ADMIN`、`CAP_NET_RAW`、`CAP_NET_BIND_SERVICE`。

---

## 七、注意事项

1. **splice 零拷贝** — 本项目默认关闭 `splice`。历史讨论曾报告部分开启 IP 转发的环境存在性能下降（见 [splice 与转发路径的注意事项](https://github.com/XTLS/Xray-core/discussions/59)），但这一现象不宜直接推广到所有环境。如需启用，建议在实际部署环境中对比吞吐量与 CPU 占用。
2. **热重载限制** — `SIGHUP` 重载时，端口转发监听地址若发生改变，旧地址上的监听 socket 会被关闭、新地址重新绑定；新旧地址冲突可能导致短暂失败，建议避免频繁变动。
3. **权限要求** — 透明代理需要 root 权限（或上述 capabilities）。
4. **配置校验** — 默认读取当前工作目录下的 `config.toml`，可用 `-c` 指定；`xtp-rs -T` 可在启动前校验并打印生效配置。
